# Лабораторная работа №14: Разработка микросервиса (Коровкин)

RESTful микросервис каталога книг («Books Microservice») с реляционной СУБД PostgreSQL, упакованный в Docker с использованием multi-stage сборки и управляемый через Docker Compose.

---

## 📋 Выполнение требований задания

| № | Требование | Реализация |
|---|---|---|
| **1** | Минимум 4 запроса (RESTful API) | Реализовано 5 основных CRUD-методов: `POST`, `GET` (список), `GET` (по ID), `PUT`, `DELETE` + `GET /health` |
| **2** | Язык программирования | **Python 3.11** (фреймворк **FastAPI** + Pydantic v2 + SQLAlchemy 2.0) |
| **3** | Реляционная СУБД | **PostgreSQL 16** |
| **4** | Совместное развертывание в контейнерах | Настроено через **Docker** и **Docker Compose** |
| **5** | docker-compose + multi-stage Dockerfile | `Dockerfile` разделен на этапы `builder` и `runner`; запуск через `docker compose up -d` |
| **6** | Исходный код в Git (GitHub / GitLab) | Готовая структура репозитория с `.gitignore` и README |
| **7** | Тестирование через Postman | В проект включен готовый файл коллекции: `postman_collection.json` |
| **8** | Обработка ошибок (не "падает", возвращает HTTP-код) | Валидация Pydantic (`422 Unprocessable Entity`), обработка несуществующих записей (`404 Not Found`), глобальный перехват сбоев (`500`) |
| **Опц.** | Логирование ошибок и действий | Настроен модуль `logging` и HTTP-middleware для фиксации каждого запроса, времени ответа и ошибок |
| **Опц.** | Документирование Swagger | Доступно автоматически по адресу `http://<IP_СЕРВЕРА>:8000/docs` и `/redoc` |

---

## 🚀 Быстрый запуск

### 1. Клонирование репозитория
```bash
git clone <URL_ВАШЕГО_РЕПОЗИТОРИЯ>
cd books-microservice
```

### 2. Запуск контейнеров
```bash
docker compose up -d --build
```

### 3. Проверка статуса
```bash
docker compose ps
docker compose logs -f web
```

Сервис станет доступен по адресу:
* **API / Swagger UI**: `http://<IP_СЕРВЕРА>:8000/docs`
* **Health Check**: `http://<IP_СЕРВЕРА>:8000/health`

---

## 📡 API Эндпоинты

| Метод | URL | Описание | Код ответа |
|---|---|---|---|
| `GET` | `/health` | Проверка доступности микросервиса | `200 OK` |
| `GET` | `/api/v1/books` | Получить список всех книг (с фильтрацией и пагинацией) | `200 OK` |
| `GET` | `/api/v1/books/{id}` | Получить книгу по идентификатору ID | `200 OK` / `404 Not Found` |
| `POST` | `/api/v1/books` | Создать новую запись о книге | `201 Created` / `422 Unprocessable` |
| `PUT` | `/api/v1/books/{id}` | Обновить существующую книгу | `200 OK` / `404 Not Found` |
| `DELETE` | `/api/v1/books/{id}` | Удалить книгу по ID | `200 OK` / `404 Not Found` |

## 🧪 Тестирование

### Вариант 1: Через интерактивный Swagger UI
1. Откройте в браузере: `http://51.250.4.226:8000/docs`
2. Нажмите на любой эндпоинт -> **Try it out** -> **Execute**.

### Вариант 2: Через Postman
1. Откройте программу **Postman**.
2. Нажмите кнопку **Import** (в левом верхнем углу).
3. Выберите файл `postman_collection.json` из папки проекта.
4. В коллекции будут настроены все сценарии:
   - Проверка работоспособности
   - Создание 2 книг (POST)
   - Получение списка и отдельной книги (GET)
   - Обновление книги (PUT)
   - Удаление книги (DELETE)
   - Сценарии проверки ошибок: передача невалидных параметров (422) и запрос несуществующего ID (404).
